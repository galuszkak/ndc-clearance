# AGENTS.md - NDC Clearance

## Project Overview

**NDC Clearance** is an interactive browser, validator, and diff tool for IATA NDC (New Distribution Capability) XML schemas. It serves airlines, travel agents, and developers working with the NDC standard.

Capabilities:
- Hierarchical browsing of XSD schema structures across NDC versions (21.3.5 through 25.4)
- Full-text search across schema elements, types, and documentation
- Side-by-side version diffing to identify schema changes
- XML validation against specific schema versions
- Worked examples from canonical shared content (`ndc_content/`) with IATA + custom sources
- Interactive Flow viewer (XState-style step graphs) with 100% coverage requirement for quality assurance
- An MCP (Model Context Protocol) server enabling AI agent integration

**Live deployment:** https://ndc-clearance.netlify.app
**MCP endpoint:** https://mcp-ndc.sunrisehikers.io/mcp/sse

This is a monorepo of three independent subprojects. Run commands from inside the relevant subdirectory.

```

├── site/                    # Frontend - Astro + Svelte static site
├── backend/                 # Backend - Kotlin/Ktor validation & MCP server
```

## site/ - Frontend

### Stack (majors that affect API surface)

Astro 7 (SSG) + Svelte 5 runes (`$state`/`$derived`/`$effect`) + Tailwind CSS 4 (via `@tailwindcss/vite`) + DaisyUI 5. Flow graphs rendered with `@xyflow/svelte` + `@dagrejs/dagre`. XML syntax highlighting via highlight.js. Sitemap via `@astrojs/sitemap`. Tooling: ESLint 10, Prettier 3, Vitest 4, `@testing-library/svelte`, TypeScript strict. Node 24 (matches CI in `deploy-site.yml`).

Exact versions live in `site/package.json` — read it; do not rely on this file for patch numbers.

### Non-obvious commands

Standard scripts (`dev`, `build`, `test`, `lint`, `format`, `preview`) are listed in `package.json`. The ones agents get wrong:

- `npm run check` — `astro check`, typechecks `.astro` + `.ts`. Run before considering site work done.
- `npm run copy-assets` — copies `../ndc_schemas/` → `public/schemas/` and `../ndc_content/examples/` → `public/content/examples/`. `dev` and `build` invoke this first; if you edit schemas/content outside `site/`, re-run it (or `copy-schemas` / `copy-content` individually) so the viewer sees fresh data.
- Dev server port is **4321**.

**Schema exploration:**

- `SchemaNode.svelte` — recursive tree node with lazy child loading, search highlight, auto-scroll
- `SchemaDiffViewer.svelte` — side-by-side version comparison with CSV export

**UI panels:** `SearchPanel` (Ctrl+F), `TreeToolbar` (zoom 50–200%, expand/collapse all), `NodePropertiesPanel` (right sidebar), `MessageSidebar` (left), `VersionSelector` (cross-version navigation).

**Content viewers:** `XmlSourceView` (syntax HL + folding + multi-file tabs), `ExamplesButton`/`ExamplesModal`, `ValidateModal` (calls backend API), `StructureOverview` (schema stats).

**Flow viewer:** `FlowsButton`/`FlowsModal` (browser), `FlowWorkspace` + `FlowGraph` (xyflow canvas), `FlowHeader` (title + source attribution).

### Performance patterns (non-obvious)

- Lazy child loading in tree nodes (on-demand resolution)
- Chunked BFS search (50-node chunks with async yields to prevent UI blocking)
- Manual DOM `classList` manipulation for search highlighting
- CSS `content-visibility` containment for large lists
- Strategic Svelte `untrack()` to break unnecessary effect dependencies

### REST API

| Method | Path        | Purpose                                          |
|--------|-------------|--------------------------------------------------|
| GET    | `/`         | Redirects to ndc-clearance.netlify.app           |

## tools/ - Kotlin CLI Tools

Independent Gradle project for schema processing and example management. Replaces former Python `scripts/`.

### Stack

Kotlin 2.4.10, Gradle (application plugin), JVM toolchain 25, Jsoup 1.22.2, JDK `java.net.http.HttpClient`, JDK `javax.xml`, `kotlinx-serialization-json`. Exact versions in `tools/build.gradle.kts`.

### Commands (named Gradle tasks — non-obvious)

```bash
cd tools
./gradlew flatten                 # Flatten all raw schemas into ndc_schemas/
./gradlew download                # Scrape IATA Confluence → ndc_content/examples/
./gradlew buildContentCatalog     # Merge iata/custom + validate flows → catalog.json
./gradlew validate                # Validate examples against flattened schemas
./gradlew validate --args='--schema-type=raw'   # Validate against raw schemas
./gradlew analyzeMissing          # Gap analysis: defined vs covered message types
./gradlew test                    # Unit tests
```

`validateFlows` and `verifyFlowCoverage` also exist (used by `buildContentCatalog`).

### Source (`src/main/kotlin/com/ndc/tools/`)

| File                         | Purpose                                                      |
|------------------------------|--------------------------------------------------------------|
| `ValidateWorkedExamples.kt`  | Validate XML vs raw/flattened schemas (consolidates 3 former Python validators) |
| `FlattenNdcSchemas.kt`       | Flatten multi-file XSD into self-contained, tree-shaken schemas (single + batch) |
| `DownloadWorkedExamples.kt`  | Scrape IATA Confluence, write canonical IATA files + source metadata |
| `BuildContentCatalog.kt`     | Build `catalog.json`, validate flow refs/message consistency, set `flow_id` |
| `AnalyzeMissingExamples.kt`  | Gap analysis: message types defined vs covered by examples   |
| `common/NdcConstants.kt`     | Shared constants: version maps, project root resolution      |
| `common/ContentModels.kt`    | Canonical content models + deterministic example ID builder   |
| `common/XmlUtils.kt`         | Shared XML utilities: message info extraction from XML files  |

### Testing

`ValidateWorkedExamplesTest.kt` — schema extraction, XML validation, well-formedness, schema path resolution.

### Data flow

```

                                                  ├→ site/public/schemas/        (via copy-assets)
```

## Development Guidelines

### Code style

- **Site:** ESLint + Prettier. 4-space indent, semicolons, trailing commas. **No `console.log`** (eslint warn level). Unused vars prefixed with `_`. Svelte 5 runes only (no stores for new component state; `stores.ts` is legacy schema-stats only).
- **Backend / Tools:** Kotlin conventions. Backend is ~750 LOC — keep it minimal.

### Architecture decisions

- Astro SSG + Svelte 5 runes for performance: static generation with islands of interactivity.
- Ktor over Spring: lightweight, coroutine-friendly.
- Schema flattening is a core value-add: tree-shaken self-contained XSDs that fit in LLM context windows.
- MCP integration lets AI agents validate NDC XML directly.
- DaisyUI for UI components without custom CSS overhead.
- Multi-file XSD support: schemas with `CommonTypes` load as separate fetches and merge client-side.

### Important patterns & gotchas

- Site consumes schemas from `public/schemas/` and examples from `public/content/examples/catalog.json`, both copied at build time from `ndc_schemas/` and `ndc_content/examples/catalog.json` respectively. Re-run `copy-assets` after changing source data.
- Backend consumes examples from `src/main/resources/content/examples/catalog.json` via `CONTENT_ROOT`; schemas from `src/main/resources/schemas/` via `SCHEMA_ROOT`. Both are CI-synced, not edited in place.
- `flow_id` is a permanent slug derived from the title (e.g., `shop-and-order-flight`) for SEO-friendly URLs — never rename an existing `flow_id`.
- Flows must have **100% step coverage** (each step has an example) to be included in `catalog.json`. `buildContentCatalog` enforces this.
- Version-to-message mapping is defined in `iata_ndc_messages.json` at the repo root.
- Worked examples carry a schema-id → version mapping (e.g., schema ID `"2134"` → version `21.3.5`) defined in `tools/src/main/kotlin/com/ndc/tools/common/NdcConstants.kt`.

### Boundaries

- Never edit generated files in `ndc_schemas/`, `site/public/schemas/`, `site/public/content/`, `backend/src/main/resources/schemas/`, or `backend/src/main/resources/content/` — regenerate them via `flatten` / `copy-assets` / CI sync.
- Never commit secrets (`.env`, `POSTHOG_API_KEY`, Netlify/Unikraft tokens).
- Do not convert the open-allowlist CORS on the backend to a restrictive policy without discussion.
- Do not commit `.gradle/`, `bin/`, `build/`, `node_modules/`, or `dist/` (already gitignored).
